# 0.9.0 사용자 피드백 보정 검증 보고서

검증일: 2026-09-22 (KST)  
대상: `codex/0.9.0-station-catalog-route-search`의 0.9.0 후보

## 결론

사용자 피드백으로 확인된 세 가지 release-blocking 결함을 보정했다.

| 영역 | 판정 | 보정 내용 |
| --- | --- | --- |
| 요일별 일평균 | 통과 | 실제 유효 관측일을 분모로 사용하고, 잘못된 달력 날짜는 평균에서 제외 |
| MOTIS 준비·재사용 | 통과 | PBF·GTFS·실행환경 fingerprint 기반 staging/cache, atomic active marker, 서버 포트 설정 및 재사용 |
| 출발·도착 정류장 검색 | 통과 | ID·이름 정확 일치, 접두어, 부분 일치, 제한적 fuzzy 순의 결정적 ranking |

이 보정으로 0.9.0 기능 후보의 사용 가능 상태는 개선되었지만, 저장소의 32-way MOTIS validation attestation이 아직 없어 `npm run release:verify`의 최종 `releaseReady`는 여전히 `false`다. 따라서 원격 push·최종 릴리스 승격은 별도 release gate로 남긴다.

## 구현 요약

- `src/core/analysis.ts`: `2024-02-31`처럼 파싱 시 자동 보정되는 날짜를 유효 날짜로 세지 않고, observed 평균을 실제 유효 관측일 수로 계산한다.
- `src/main/motis-preparation-cache.ts`: PBF SHA-256, current GTFS content hash, MOTIS binary identity와 준비 옵션을 fingerprint로 묶고 fingerprint별 staging 디렉터리를 사용한다. 성공한 import 뒤에만 active marker를 atomic replace한다.
- `src/main/motis-sidecar.ts`: Windows 설치 경로의 공백을 피하기 위해 import를 data directory의 상대 경로로 실행하고, 관리 loopback host/port를 generated config에 기록한다.
- `src/main/motis-ipc.ts`·`src/preload/index.ts`·`src/renderer/RouteSearchWorkspace.tsx`: `checking → configuring → importing → ready → starting → querying` 단계와 operation ID를 전달하고, 준비 중 입력을 잠근다.
- `src/core/scenario-search.ts`: 이름·ID 검색 후보를 동일한 규칙으로 정렬하고 기존 Route Search는 현재 `routeStops`만 후보로 사용한다.

## Packaged native-flow smoke

Electron 패키지와 번들 MOTIS 실행 파일을 실제 프로세스로 기동하고 CDP로 화면을 조작하는 packaged smoke를 실행했다. 실행 파일은 [0.9.0 unpacked 앱](../../release/win-unpacked/Transit%20Analysis%20Platform.exe)이며, 결과는 [Route Search smoke 결과](../../test-artifacts/packaged-smoke/2026-09-22T11-47-16.800Z/result.json)와 [실행 로그](../../test-artifacts/packaged-smoke/2026-09-22T11-47-16.800Z/process.log)에 남아 있다.

확인한 흐름:

- 앱·프로젝트 routing 위치의 PBF 자동 탐색 및 SHA-256 확인
- Leaflet 경로탐색 지도 표시
- 정류장 검색으로 출발지 `A`, 도착지 `B` 선택 및 endpoint 동기화
- 첫 검색에서 PBF 기반 MOTIS `config/import`와 server readiness 완료
- 동일 입력의 두 번째 검색에서 `cacheHit: true`, `config/import/starting` 재실행 없음
- 경로 결과 카드·지도 상태 렌더링
- 기존 3D, 하차 추정, 노선 분석, OD, GTFS Before/After 흐름 회귀 확인
- renderer errors 0건

사용한 PBF는 `287,629,706` bytes, SHA-256은 `68ED4BBB72E41B73421E28D8282D82E5FC6F4A2CB78A0913B6812D32AA910252`다. 번들 MOTIS는 manifest v2의 `v2.11.3`이며 `motis.exe` SHA-256은 `d91627ab9f74959fb97dd2996c5df610059b565d29f95a1358056a4b7b458bff`다.

PBF가 없는 상태의 Geofabrik 안내는 bounded resolver 및 renderer 계약 테스트로 확인했다. 이번 packaged native-flow 실행은 실제 경로 결과를 확인하기 위해 준비된 PBF를 사용했으며, PBF 부재 창을 별도 수동 acceptance로 다시 실행한 결과는 이 보고서에 포함하지 않는다.

## 알려진 release gate

`npm run release:verify`가 실패한 이유는 이번 보정 기능이 아니라 저장소에 필요한 32-way MOTIS validation attestation 파일이 없는 것이다.

```text
releaseReady: false
motis-artifact-and-actual-data: 32-way validation attestation unavailable
boundary-validation: 32-way attestation is unavailable
app-regression: passed
packaged-smoke: passed
```

따라서 현재 판정은 `0.9.0 구현·패키지·실사용 경로 검증 통과 / 최종 release gate 미충족`이다.

# 0.6.1 구축 및 검증 결과

기준일: 2026-09-18. 구현 범위와 미결사항 분류: [구축계획](../plans/2026-09-18-v0.6.1-stabilization.md).

## 구현

1. OD 캐시: 데이터 배열·필터·분모가 같으면 관측/고신뢰/기대값 각각의 결과를 재사용한다. 동시 동일 요청도 합치고 실패한 요청은 제거한다. 현재 조건의 최대 3개 결과만 유지한다.
2. 저장 분리: Electron에서 원본 배열이 동일하면 records를 IPC로 전송하지 않고 최신 메타데이터를 `project-state.json`에 원자적으로 저장한다. 원본 변경은 전체 저장, 목록/복원은 원본과 최신 상태를 결합한다. 프로젝트별 저장은 직렬화한다.
3. 오류 안내: 누락 ID를 우선 분류한 뒤 ID가 모두 있는 순번 오류를 별도 집계한다. JS/DuckDB 모두 같은 안내를 제공하며 기존 제외행 합계를 유지한다.

## 자동 검증

- `npm test`: 47개 파일, 239개 테스트 통과.
- 추가 회귀 테스트: 캐시 반복/동시 요청, 필터·분모·데이터 무효화, 실패 재시도, 원본 파일 불변, 재시작 후 설정 복원, 전체 저장 후 상태 초기화, 잘못된 저장 요청, JS/DuckDB 오류 분리.
- 기존 오류 문구 테스트는 수정 전 실패, 수정 후 통과를 확인했다.
- `npm run build`: TypeScript project build와 Electron main/preload/renderer 번들 통과.
- `npm run typecheck`, `git diff --check`: 통과.
- 첫 테스트 실행은 sandbox `spawn EPERM`, 실데이터 첫 실행 요청은 승인 검토 서비스 사용량 한도로 시작되지 않았다. 승인된 재실행으로 검증을 완료했다. 앱 실패로 집계하지 않는다.

메타데이터 벤치마크는 설정 위주의 최소 manifest다. 실제 앱은 정류장/노선 사전과 분석 결과도 저장하므로 동일한 저장시간을 보장하지 않는다. 캐시 시간은 함수 조회 비용이며 Electron IPC, 지도·표 렌더링, 사용자 클릭 지연을 포함하지 않는다. 0.6.0 수동 체감 20초와 직접적인 개선 배수로 비교하지 않는다.

동일 폴더의 테스트 프로젝트에는 로컬 실데이터가 있으므로 저장소에 포함하지 않는다. 집계 보고서에는 카드번호나 거래행을 기록하지 않는다.

## Windows 배포 앱 검증

- `npm run package:win`: 0.6.1 NSIS 생성 및 내장 MOTIS 파일 확인 통과.
- `node scripts/smoke-packaged.mjs`: 격리된 테스트 프로필의 실제 Windows 실행 파일로 6단계 통과, renderer 예외 0건.
- CJS preload/프로젝트 IPC/내장 MOTIS 기본 경로, 3D WebGL, 하차 추정 저장, 노선 추정값 5→15, GTFS Before/After 생성을 확인했다.
- OD 추정값 5→15→5→15 전환 후 원본 JSON 내용과 DuckDB 수정시각 불변을 확인했다. 페이지 reload 후 프로젝트 목록과 분석 화면에서 고신뢰 설정 및 합계 15 복원을 확인했다.
- 증빙: `test-artifacts/packaged-smoke/2026-09-19T01-03-46.002Z/result.json`, 같은 폴더의 3D/GTFS PNG.
- 설치 파일: `release/TransitAnalysisPlatform-0.6.1-setup.exe`, 153,693,346 bytes. 설치 실행은 하지 않았으며, 검증 대상은 같은 빌드의 `win-unpacked`다.
- 설치 파일 SHA-256: `3B004734392D1F147AAC8D0181D6EC35F131F9B0A904ACDB6FD7B4D114D1590D`.
- MOTIS 바이너리나 시나리오 코드는 이번에 바꾸지 않았다. 실제 MOTIS import/route 시나리오를 재실행한 결과로 주장하지 않으며, 기존 자동 회귀 테스트와 packaged 런타임 경로만 재검증했다.

- DOCX: `docs/test-reports/2026-09-19-yeosu-computer-use-report.docx`

## 후속 범위 포함 결과

0.6.1 후속 범위 중 사용자가 지정한 도로망 shape, 대규모 MOTIS, 7일 UI 검증을 구현하고 검증했다.

- 도로망 shape: 실제 여수시 20개 노선의 2,804개 구간을 BUS 프로파일로 조회해 1,862개 OSM 형상(66.41%)과 942개 직선 대체를 확인했다. GeoJSON LineString·끝점·way 검증, 회로 차단, 짧은 연결선/우회비율 경고, 2D·3D 경로 재사용을 포함한다. 상세 결과는 `docs/test-reports/2026-09-18-road-shapes.md`와 `test-artifacts/road-shapes/evaluation-real.json`에 있다.
- 대규모 MOTIS: 실제 여수 ROUTESTTN 77개 노선·1,611개 물리 정류장으로 Before/After 각각 240,000건(총 480,000건)을 완료했다. 두 패키지 모두 HTTP 오류 0건, 무경로 72건이며 처리량은 Before 784.1 OD/s, After 285.8 OD/s였다. 결과와 해석은 `docs/benchmarks/2026-09-18-motis-matrix.md`에 있다.
- 7일 UI: 실제 7일 파일을 패키지 앱의 DOM 입력으로 불러와 762,499건을 검증했다. 매핑·날짜 범위·추정·요일/OD/노선 화면·고신뢰/기대흐름 전환·3D·반복 전환·reload 상태 복원과 렌더러 오류 0건을 확인했다. 상세 결과는 `docs/test-reports/2026-09-18-week-ui.md`와 `test-artifacts/week-ui/2026-09-19T00-38-53.031Z/result.json`에 있다.

## 잔여 범위

- 이번 요청에서 제외한 운임 엔진, BIS 기반 운행시간 보정, 차량 운영 제약, 공식 Windows tiles, 3D underlay/WebGPU 및 추가 분석 화면은 0.6.1 후속 과제로 남는다.
- 7일 UI 실행은 기능 검증을 통과했지만 전체 화면의 부드러운 응답성과 장시간 메모리 안정성을 보장하지 않는다. 실제 7일 렌더러 측정에서 최대 타이머 지연 33.8초와 명시적 GC 후 약 525MiB heap을 기록했다.
- 287MB 전국 OSM PBF를 새 패키지 프로필에서 준비하는 선택 스모크는 15분 동안 완료 신호가 없어 중단했다. 실제 네이티브 BUS 형상 2,804구간 검증과 기본 패키지 스모크는 통과했으며, 대용량 PBF 최초 import 시간은 별도 최적화·측정 과제로 남는다.
- Windows 설치/업그레이드와 다양한 GPU 조합의 수동 검증은 별도로 남는다.

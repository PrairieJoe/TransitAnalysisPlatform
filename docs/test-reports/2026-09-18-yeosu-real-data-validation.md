# 여수시 실데이터 수동 검증 — 2026-09-18

## 목적

통합된 Electron 앱에 실제 여수시 교통카드 원천 데이터를 입력해 파일 매핑, 하차 추정, OD 하차 추정값 적용, 노선 혼잡도와 3D 시각화의 사용자 흐름을 확인한다. 이 보고서는 자동화 테스트와 별도로 사용자가 실제 화면에서 확인한 결과를 기록한다.

## 입력 데이터

검증에는 `C:\Users\User\Desktop\Study\교통카드모음\1. 여수시\2. 교통카드`의 2024-04-15 하루분을 사용했다.

| 파일 | 크기 | 행 수/역할 |
| --- | ---: | --- |
| `DWTCD_20240415.dat` | 약 15.9MB | 105,412행 거래내역 |
| `STTN_20240415.dat` | 약 0.3MB | 정류장정보, 약 2,686행 |
| `ROUTESTTN_20240415.dat` | 약 2.6MB | 노선별 경유정류장정보, 약 27,741행 |

같은 폴더의 2024-04-15~21 거래내역 합계는 약 109.8MB이다. 일주일 전체 처리시간은 이번 수동 검증에 포함하지 않았다.

## 사용자 수행 결과

| 단계 | 결과 | 체감 시간 |
| --- | --- | ---: |
| 거래내역 선택·미리보기·자동 매핑 | 정상 | 대기 거의 없음 |
| 정류장정보 선택·매핑 | 정상, 경고 없음 | 거의 즉시 |
| 노선별 경유정류장정보 선택·매핑 | 정상, 오류 없음 | 거의 즉시 |
| 하차 추정 실행 | 요일별 분석 화면으로 정상 이동 | 약 20초 |
| OD 흐름 전환 | 탭 활성화, `하차 추정값 사용` 표시 | 정상 |
| 하차 추정 포함 범위 변경 | 고신뢰·기대값 모두 선택 가능 | 매번 지연 발생 |
| 노선 혼잡도 분석 | 결과·2D·3D 표시 | 약 20초 |

3D의 높낮이는 정류장별 피크 재차인원/수요를 나타내는 분석용 값이며, 지형 고저차나 실제 도로망을 의미하지 않는다. 현재 2D·3D 노선 도면은 정류장 좌표 기반의 분석용 구간 표현이다.

## 확인된 이슈

### OD 하차 추정값 토글 지연

현재 `하차 추정값 사용` 또는 `고신뢰·기대값 모두`를 변경할 때마다 전체 OD 집계와 프로젝트 저장이 다시 수행된다. 하차 추정 자체를 다시 계산하는 것은 아니지만, 105,412행을 대상으로 관측·고신뢰·기대값 기준을 다시 집계하고 `records.duckdb`를 다시 저장하므로 화면 전환에 지연이 발생한다.

개선 방향은 하차 추정 완료 시 관측·고신뢰·기대값 OD 집계를 캐시하고, 토글 시 캐시 결과만 교체하는 것이다. 토글 변경만으로 전체 원본 DB를 다시 쓰지 않도록 저장 범위도 분리해야 한다.

### 데이터 품질 안내 문구

기존 소규모 여수 샘플에서 `경유정류장순번오류` 8건이 확인됐다. 이 8건은 하차 ID가 비어 있는 행이 아니라 승차·하차 정류장 순서가 역방향인 행이다. OD 경고가 이를 “승차 또는 하차 정류장 ID가 없어 제외”로 함께 설명하므로, 오류 유형별 안내 문구를 분리할 필요가 있다.

## 재현 절차

1. 새 분석을 시작한다.
2. `DWTCD_20240415.dat`, `STTN_20240415.dat`, `ROUTESTTN_20240415.dat`를 거래·정류장·노선별 정류장 단계에 각각 연결한다.
3. 자동 매핑을 확인하고 `입력 완료 → 하차 추정`을 선택한다.
4. 기본 설정으로 하차 추정을 실행한다.
5. `OD 흐름`에서 `하차 추정값 사용`을 켜고 `고신뢰·기대값 모두`를 선택한다.
6. `노선 혼잡도`에서 노선을 선택하고 2D·3D 상세 도면과 정류장별 표의 선택 동기화를 확인한다.

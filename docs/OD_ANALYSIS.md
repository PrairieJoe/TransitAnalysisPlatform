# OD 통행량 분석 동결 기준

이 문서는 Transit Analysis Platform `0.5.2` 동결 기준의 OD(Origin–Destination) 통행량 분석 동작을 기록합니다. OD 기능의 입력 계약, 집계 기준, 지도 표현, 예외 처리 및 검증 범위를 한 곳에서 확인하기 위한 문서입니다.

## 사용자 흐름

1. 교통카드 거래내역 파일을 불러옵니다.
2. 거래내역 매핑 화면에서 `승차 정류장 ID`와 `하차 정류장 ID`를 연결합니다.
3. 정류장 정보 파일을 불러와 `정류장 ID`, `정류장 명칭`, `위도`, `경도`를 연결합니다.
4. 기간·노선·지역·분모 기준을 설정하고 분석을 실행합니다.
5. 보고서의 `OD 흐름` 탭에서 지도와 표를 확인합니다.

승차·하차 ID 연결은 기존 요일별 분석의 필수 조건이 아닙니다. 따라서 기존 파일이나 기존 프로젝트는 OD 필드가 없어도 요일별·시간대별·정류장별 분석을 계속 사용할 수 있습니다.

## 입력 및 자동 매핑

표준 28필드 무헤더 거래내역의 기본 제안은 다음과 같습니다.

| 분석 역할 | 기본 제안 | 용도 |
| --- | --- | --- |
| 날짜 | `필드1` | 서비스 날짜와 분모 계산 |
| 승차 시간 | `필드15` | 시간대 분석 및 날짜 보완 |
| 승차 정류장 ID | `필드17` | OD의 Origin 및 정류장 수요 |
| 하차 정류장 ID | `필드20` | OD의 Destination |
| 승차인원 | `필드25` | 합산 집계 |
| 노선 | `필드13` | 필터 |

헤더가 있는 파일은 의미 있는 헤더명을 우선 사용합니다. 위치 기반 제안은 28개 필드의 표준 배치에 한정되며, 모든 제안값은 사용자가 가져오기 화면에서 수정할 수 있습니다.

## 집계 기준

- 각 행은 `승차 정류장 ID + 하차 정류장 ID` 조합으로 묶습니다.
- 선택 기간의 조합별 총 승차인원을 계산합니다.
- `실제 관측일` 기준이면 선택 조건에 유효한 OD 데이터가 존재하는 관측일 전체를 공통 분모로, `전체 날짜` 기준이면 선택 기간의 모든 날짜를 공통 분모로 사용합니다.
- 결과는 일평균 값 내림차순, Origin ID, Destination ID 순으로 정렬하고 순위를 부여합니다.
- 승차 또는 하차 ID가 비어 있는 행은 OD 집계에서 제외하며 제외 행 수를 경고합니다.
- 노선 순번상 역방향으로 판정된 `경유정류장순번오류` 행은 OD 집계에서 제외합니다. 노선 ID가 없거나 노선 경로에 정류장이 등록되지 않은지는 OD 집계 조건으로 사용하지 않습니다.
- 동일한 Origin–Destination 쌍은 하나의 흐름으로 합산합니다.

화살표 방향이나 지도 좌표는 집계 후 정류장 사전과 조인하는 단계에서 결정됩니다. 즉, 집계 결과와 지도 표시 가능 여부를 분리하여 표의 데이터 손실을 방지합니다.

## 지도 표현 기준

현재 동결 버전의 지도는 Leaflet을 사용하며, 정류장 사전의 두 좌표가 모두 있는 흐름만 표시합니다.

### 흐름선

- Origin 좌표에서 Destination 좌표로 향하는 25개 점의 2차 베지어 곡선을 그립니다.
- 곡선 제어점은 두 좌표의 중간점에서 직교 방향으로 이동합니다.
- 일반 흐름선은 빨간색 반투명 선이며, 선택한 표 행의 흐름은 더 짙은 빨간색과 굵은 선으로 강조합니다.
- 선 굵기는 조합별 일평균 수요의 제곱근 비율로 보정하여 큰 흐름의 시각적 우세를 완화합니다.
- 지도에는 상위 일부가 아니라 집계된 모든 매칭 흐름을 표시합니다.

### 화살표

- 화살촉은 곡선의 약 84% 지점에 삼각형으로 배치합니다.
- 곡선의 진행 방향을 접선으로 계산하므로 화살촉의 꼭짓점은 항상 Origin에서 Destination 쪽을 향합니다.
- 범례의 `▶ 하차 방향`은 화살촉이 하차 정류장을 가리킨다는 의미입니다.

### 겹침과 특수 형태

- A→B와 B→A는 같은 직선에 겹치지 않도록 곡선의 물리적 반대편으로 분리됩니다.
- A→A는 두 좌표가 같아지는 경우이므로 작은 오프셋을 제어점에 적용해 자기고리 형태로 표시합니다.
- 한쪽이라도 정류장 사전에 없거나 좌표가 없으면 흐름선과 양 끝점 모두 지도에서 제외합니다.
- 지도 배경 타일을 불러오지 못해도 데이터 흐름선은 계속 표시하며, 재시도 안내를 제공합니다.

## 표와 내보내기

OD 표에는 순위, 승차 정류장, 하차 정류장, 일평균 이용인원을 표시합니다.

- 열 제목을 눌러 정렬할 수 있습니다.
- 행을 선택하면 동일한 흐름을 지도에서 강조합니다.
- `엑셀` 내보내기는 `OD분석` 시트를 생성하고 분석 기간, 분모 기준, 선택 기간 일수를 함께 기록합니다.
- 보고서의 PNG·PDF 내보내기는 지도와 표가 포함된 OD 보고서 화면을 대상으로 합니다.
- 프로젝트 백업·복원에는 OD 결과, 분석 모드, 표시 단위, 정류장 사전이 함께 저장됩니다.

## 정류장 사전 예외 처리

거래내역 ID와 정류장 사전 ID는 문자열 기준으로 정확히 일치해야 합니다. 매칭 결과는 다음과 같이 처리합니다.

| 상황 | 표 | 지도 | 경고 |
| --- | --- | --- | --- |
| 양쪽 ID·좌표 모두 매칭 | 정류장 명칭 표시 | 흐름 표시 | 없음 |
| 승차 ID 미매칭 | 승차 정류장에 `사전 미등록` | 해당 흐름 제외 | `승차 정류장 사전에 없는 ID N개...` |
| 하차 ID 미매칭 | 하차 정류장에 `사전 미등록` | 해당 흐름 제외 | `하차 정류장 사전에 없는 ID N개...` |
| 거래내역 승차·하차 ID 누락 | OD 결과에서 제외 | 표시하지 않음 | 제외 행 수 경고 |

여수 샘플의 거래내역 24행에는 의도적인 예외값 승차 ID `999999999`가 있습니다. 샘플 정류장 사전에 이 ID를 넣지 않았기 때문에, 샘플 실행 시 승차 정류장 미매칭 경고가 1건 발생하는 것이 정상입니다.

## 동결 검증 범위

동결 시점에는 다음 검증을 통과해야 합니다.

- `npm test`: 전체 테스트 통과
- `npm run typecheck`: 타입 검사 통과
- `npm run build`: Electron 렌더러·메인 번들 생성 통과
- `npm run package:win`: Windows 설치파일 및 `win-unpacked` 생성 통과
- 샘플 거래내역·정류장 사전으로 OD 탭 진입, 흐름선·화살표·표 행 선택, 프로젝트 복원 확인

### 현재 동결의 범위와 한계

- 지도 선은 실제 도로망 경로가 아니라 두 정류장 좌표 사이의 시각화용 곡선입니다.
- 정류장 사전은 자동 지오코딩하지 않으며, 사용자가 파일을 제공해야 합니다.
- OSM 배경 타일은 네트워크 상태에 따라 로딩되지 않을 수 있습니다.
- 화살표·선 굵기·곡선 오프셋은 이 버전의 시각화 계약이며, 변경 시 다음 버전의 문서와 테스트를 함께 갱신해야 합니다.

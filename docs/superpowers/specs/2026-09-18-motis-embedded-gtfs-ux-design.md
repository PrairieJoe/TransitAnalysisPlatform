# MOTIS 내장 실행 및 Synthetic GTFS 사용자 흐름 개선 설계

## 목표

사용자가 데이터 매칭을 마친 뒤 분석 결과 화면을 거치지 않고 바로 Synthetic GTFS 구축으로 이동할 수 있게 한다. MOTIS는 사용자가 실행 파일·작업 폴더·포트를 설정하지 않아도 앱 내장 구성요소로 실행되게 하며, Synthetic GTFS 생성 화면은 노선 운행 가정만 최소 입력하도록 단순화한다.

## 범위

### 1. 데이터 매칭 후 진입 흐름

노선별 정류장정보 매핑이 완료된 마지막 가져오기 단계에 다음 두 경로를 제공한다.

- `분석 실행`: 기존 분석 결과 화면으로 이동
- `GTFS 구축`: 프로젝트를 저장한 뒤 Synthetic GTFS 화면으로 직접 이동

직접 이동하더라도 프로젝트에는 거래내역·정류장정보·노선별 정류장정보와 기본 분석 결과가 저장되어야 한다. Synthetic GTFS 화면의 뒤로가기는 분석 결과 화면으로 이동하고, 분석 결과 화면에서는 GTFS 구축 화면으로 다시 이동할 수 있어야 한다.

### 2. MOTIS 실행 위치와 작업 데이터

- 배포본은 `process.resourcesPath/motis/motis.exe`만 MOTIS 실행 파일로 사용한다.
- 사용자가 실행 파일 경로를 입력하거나 외부 `C:\motis` 경로를 지정하는 UI는 제공하지 않는다.
- MOTIS import/server가 생성하는 변경 데이터는 `%LOCALAPPDATA%\\Transit Analysis Platform\\motis-data` 아래 앱 전용 폴더를 사용한다.
- 포트는 main process가 `127.0.0.1`에서 사용 가능한 포트를 자동 선택한다.
- 설치본에서 내장 MOTIS 파일이 없으면 설치 구성요소 누락 오류를 표시한다.
- 개발 환경은 저장소의 patched MOTIS를 fallback으로 사용할 수 있지만, 이 override는 배포 사용자 UI나 배포 설정에 노출하지 않는다.
- 지도 타일은 계속 비활성화한다.

설치 폴더에는 실행 파일과 읽기 전용 리소스만 두고, MOTIS 작업 데이터는 쓰기 가능한 로컬 앱 데이터에 둔다. 이 분리는 `Program Files` 권한, 앱 업데이트, 대용량 파일 관리 문제를 피하기 위한 것이다.

### 3. Synthetic GTFS 최소 입력

기본 화면에 노출하는 입력은 다음으로 제한한다.

- 분석 노선
- 운행대수
- 운행 시작 시각
- 운행 종료 시각
- 배차간격(분)
- After 시나리오 정류장 ID

배차간격을 입력하면 운행 시작·종료 시각을 기준으로 방향별 운행횟수를 계산한다. 기존의 운행횟수 직접 입력은 고급 설정으로 이동하거나 배차간격과 상호 배타적인 선택형 입력으로 제공하지 않는다.

운행대수는 현재 실제 차량 배정 데이터가 없으므로 GTFS의 trip 생성에 임의로 차량을 배정하지 않는다. 대신 입력 가정과 provenance에 기록하고, 결과 설명에 “차량 배정은 실제 운행자료가 없어 검증하지 않음”을 명시한다. 향후 차량 블록·회차 모델을 추가할 수 있도록 데이터 구조 확장은 별도 작업으로 남긴다.

기본값으로 처리하는 항목은 평일 운행, 서비스 기간, 정차시간, 역방향 파생, 기관명이다. 사용자가 조정해야 하는 경우 `고급 설정`에서 변경한다.

### 4. Before/After 설명과 결과 표시

생성 전에는 다음을 고정 문구로 설명한다.

- Before: 현재 노선별 정류장정보를 바탕으로 만든 기준 운행계획
- After: 사용자가 입력한 정류장 순서를 반영한 개편 운행계획
- 두 결과의 차이는 정류장 순서·정류장 수·추정 운행시간·여정 결과에 나타남
- 공식 시간표가 없거나 shape가 없는 값은 추정이며 실제 운행 사실을 보장하지 않음

생성 후에는 다음 순서로 표시한다.

1. 입력 요약: 노선, 운행대수, 운행시간대, 배차간격, 정류장 수
2. Scenario Delta: 추가·제거·유지 정류장과 기준/After 경로
3. 결과 읽는 법: Trip 수, 추정 필드, Before/After 비교의 의미
4. 주의사항: 추정 데이터·OSM routing·차량 배정 미검증
5. 기술 상세: 생성 파일 목록과 provenance를 접힌 상세 영역으로 표시

## 데이터 흐름

```text
노선 매핑 완료
  ├─ 분석 실행 ───────────────> report
  └─ GTFS 구축 ─> project save -> synthetic builder

synthetic builder
  ├─ 최소 입력 + 고급 기본값
  ├─ Synthetic GTFS Before/After 생성
  └─ main IPC -> embedded MOTIS + LocalAppData 작업폴더 + 자동 포트
```

## 오류 처리

- 내장 MOTIS 실행 파일 누락: “설치본의 MOTIS 구성요소가 없습니다. 앱을 다시 설치하세요.”
- MOTIS 작업 폴더 생성 실패: 실제 경로와 권한 확인 안내
- 자동 포트 선택 실패: 재시도 가능한 오류와 점유 포트 후보 표시
- 운행대수·시간대·배차간격이 유효하지 않음: 입력 필드 가까이에 원인 표시
- After 경로가 2개 미만이거나 존재하지 않는 정류장 포함: 정류장 ID와 원인 표시

## 검증 기준

- 가져오기 마지막 단계에서 `GTFS 구축`을 누르면 분석 결과를 거치지 않고 builder가 열린다.
- 패키지 실행 시 MOTIS 실행 경로가 `resources/motis/motis.exe`이며 외부 경로 입력이 필요 없다.
- MOTIS 작업 데이터가 `%LOCALAPPDATA%` 앱 전용 폴더에 생성되고 포트가 자동 선택된다.
- 기존 Synthetic GTFS 시나리오 결과와 새 배차간격 입력 결과의 운행횟수가 일치한다.
- 기본 화면에 최소 입력만 보이고 고급 설정은 접혀 있다.
- Before/After 설명과 결과 요약이 사용자 관점에서 이해 가능하다.
- 기존 테스트, 새 단위 테스트, production build, 패키지 smoke test가 통과한다.

## 제외 범위

- MOTIS 지도 타일과 벡터 타일 서버
- 앱 내부 PBF 자동 다운로드
- 실제 차량 블록·회차·차량별 trip 배정
- 공식 대중교통 시간표와 Synthetic GTFS의 자동 대체

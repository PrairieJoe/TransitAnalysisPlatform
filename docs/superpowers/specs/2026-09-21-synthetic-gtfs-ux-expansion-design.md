# 0.8.0 Synthetic GTFS UX 확장 설계

## 배경

현재 0.8.0의 Synthetic GTFS 개선은 긴 화면을 네 단계로 분리했지만, 사용자의 실제 이해 방식까지 충분히 반영하지 못했다. `GTFS 구축`이 추정방법 설정·프로젝트 백업·엑셀·PNG·PDF와 같은 보고서 유틸리티 버튼과 같은 줄에 놓여 기능의 성격이 흐려지고, 시나리오 화면은 라벨·Before 경로·운행조건을 한꺼번에 요구하는 일반 폼처럼 보인다.

사용자가 기대하는 시나리오는 GTFS 파일을 직접 작성하는 작업이 아니다. 현재 노선을 기준으로 정류장이나 운행조건을 바꾼 개편안을 만들고, 동일한 출발지·도착지·출발시각에서 현행과 개편안의 효과를 비교하는 계획 작업이다.

이번 확장은 아직 원격에 push되거나 배포되지 않은 0.8.0 범위 안에서 수행한다. 0.8.1 또는 0.9.0으로 버전을 올리지 않는다.

## 목표

1. Synthetic GTFS를 보고서 유틸리티가 아닌 별도 계획·시나리오 기능으로 발견하게 한다.
2. 사용자가 원시 GTFS 필드나 긴 문자열을 작성하지 않고 현행 노선의 변경점을 편집하게 한다.
3. 현행 노선과 개편 시나리오의 관계를 화면·데이터·비교 결과에서 일관되게 표현한다.
4. 기존 GTFS 생성 알고리즘, provenance, ZIP 내보내기, MOTIS IPC와 결과 계산을 보존한다.
5. 신규 UI를 네이티브 Electron 화면에서 테스트할 수 있고, 현재 기능을 잃지 않도록 회귀 기준을 만든다.

## 비목표

- Naver·Kakao·Google 지도 API를 연동하거나 외부 지도 결과를 복제하지 않는다.
- Synthetic GTFS 생성 알고리즘이나 MOTIS sidecar의 데이터 계약을 변경하지 않는다.
- 프로젝트 schema version을 올리지 않는다. 기존 `ScenarioDefinition` 저장 호환성을 유지한다.
- 혼잡도 분석을 시나리오의 부모 기능으로 만들지 않는다.

## 정보구조

보고서 화면은 분석과 계획을 분리한다.

```text
분석 결과
├─ 분석
│  ├─ 요일별 분석
│  ├─ 시간대 분석
│  ├─ 정류장 수요
│  ├─ OD 흐름
│  ├─ 노선 혼잡도
│  └─ 데이터 품질 현황
└─ 계획·시나리오
   └─ 노선 개편 시나리오
```

`노선 개편 시나리오`는 추정방법 설정, 프로젝트 백업, 엑셀, PNG, PDF와 같은 유틸리티 버튼 영역에 두지 않는다. 보고서 내 별도 계획 영역 또는 분리된 계획 탭으로 제공하며, 노선별 정류장정보가 없으면 비활성화하고 그 이유를 표시한다.

기존의 분석 결과 헤더에는 데이터 내보내기와 프로젝트 관리 기능만 남긴다. Synthetic 화면의 메인 명칭은 `GTFS 구축`보다 `노선 개편 시나리오`를 우선 사용하고, GTFS는 내부 생성 단계의 산출물로 설명한다.

## 사용자 흐름

```text
분석 결과
  → 계획·시나리오
  → 노선 개편 시나리오
  → 현행 노선 선택
  → 정류장 변경
  → 변경안 확인·저장
  → 현행/개편안 GTFS 생성
  → 동일 조건 여정 비교
```

첫 진입 화면은 사용자가 선택한 현행 노선과 현재 정류장 목록을 보여준다. 시나리오 라벨은 자동 기본값을 제공하고 선택 입력으로 낮춘다. 사용자는 저장된 시나리오를 고르거나 새 시나리오를 만들 수 있다.

## 시나리오 편집 UX

### 현행 노선

- 노선 선택은 노선명·노선 ID·교통수단을 함께 보여준다.
- 선택 직후 현행 정류장을 세로 목록으로 표시한다.
- 각 정류장 행은 순번, 정류장명, 정류장 ID를 보여준다.
- 현행 목록은 읽기 기준선이며, 변경 조작은 개편안 목록에서 수행한다.

### 개편안 편집

- 개편안은 현행 목록에서 시작한다.
- 정류장 추가는 정류장명·ID 검색형 입력으로 수행한다.
- 정류장 삭제는 행 단위 버튼으로 수행한다.
- 순서 변경은 행의 위로 이동·아래로 이동 조작으로 수행한다. 키보드와 마우스에서 동일하게 사용할 수 있어야 한다.
- 각 행에는 `현행`, `추가`, `삭제`, `순서 변경` 상태를 표시한다.
- 현행과 동일한 경우에는 변경 없음 상태를 명확히 보여준다.
- 원시 쉼표 문자열 입력은 기본 화면에서 제거하고, 필요한 경우 `정류장 ID 직접 입력` 고급 영역으로 제한한다.

### 운행조건

- 개편안은 현행 운행조건을 기본값으로 상속한다.
- 첫차·막차·배차간격·운행대수·서비스 기간·운행요일은 기본 화면에서 반복해서 요구하지 않는다.
- 운행조건을 바꿀 때만 `운행조건 변경` disclosure를 열어 변경 항목을 편집한다.
- Before와 After의 전체 운행조건을 나란히 펼쳐 보여주는 구조는 사용하지 않는다.

### 라벨과 저장

- 기본 라벨은 선택 노선과 변경 상태를 이용해 자동 생성한다. 예: `101번 정류장 개편안`.
- 사용자가 직접 라벨을 바꾸는 입력은 보조 정보로 배치한다.
- 저장 버튼은 `시나리오 저장`으로 표현한다.
- 저장 후에는 선택한 현행 노선, 변경 요약, 마지막 저장 시각을 요약 카드로 표시한다.

## 비교 의미와 결과

시나리오 비교는 다음 두 버전을 명확히 구분한다.

- `현행`: 프로젝트의 현재 노선별 정류장정보와 운행조건으로 생성한 기준 GTFS
- `개편안`: 사용자가 편집한 정류장 변경과 선택한 운행조건으로 생성한 After GTFS

동일한 출발지·도착지·출발시각을 두 버전에 적용한다. 결과 화면은 다음을 함께 보여준다.

- 현행/개편안 정류장 변경 요약
- 동일 OD의 총 소요시간, 차량 탑승시간, 초기 대기, 환승, 보행 결과
- 여정 미발견 여부와 경고
- 시간창 반복 검증의 평균·중앙값·P90

사용자에게는 `현재 결과를 대체`하는 기능처럼 보이지 않도록 `현행`과 `개편안`을 항상 병기한다. 입력 변경 뒤 생성·MOTIS·반복 결과는 기존처럼 stale 상태로 표시하고 다시 실행을 요구한다.

## 컴포넌트 및 데이터 경계

- `App.tsx`: 보고서의 분석/계획 영역과 `노선 개편 시나리오` 진입을 담당한다.
- `ScenarioWorkspaceEntry.tsx`: 계획 영역의 안내 카드, 진입 버튼, 노선정보 필요 상태를 담당한다.
- `SyntheticGtfsBuilder.tsx`: 현재 노선·개편안·생성·비교 상태를 조정하고 단계 이동을 담당한다.
- `SyntheticScenarioStep.tsx`: 사용자용 시나리오 작업공간을 제공한다.
- `SyntheticRouteScenarioEditor.tsx`: 현행/개편안 정류장 목록, 추가·삭제·순서 변경, 변경 diff를 담당한다.
- `ScenarioDefinitionEditor.tsx`: 기존 저장 계약과 고급 다중 노선/여정 입력 호환을 유지하되, 첫 진입 화면의 주 UI로 직접 노출하지 않는다.
- `SyntheticGenerationStep.tsx`: 현행/개편안 GTFS 생성과 산출물 검수를 담당한다.
- `SyntheticMotisStep.tsx`, `SyntheticBatchStep.tsx`: 동일 조건 여정 비교와 반복 검증을 담당한다.

새 편집기는 기존 `ScenarioDefinition`으로 저장 가능한 형태로 변환한다. 기존 `buildSyntheticGtfsDraft`, `createScenarioDelta`, MOTIS preload API와 main IPC 경계는 유지한다. 사용자가 편집한 정류장 배열과 변경된 운행조건만 기존 생성 coordinator에 전달한다.

## 검증 기준

### 진입 및 정보구조

- 보고서 헤더 유틸리티 영역에 `GTFS 구축`이 렌더링되지 않는다.
- 계획·시나리오 영역에 `노선 개편 시나리오`가 표시된다.
- 노선별 정류장정보가 없으면 진입 버튼이 잠기고 이유를 표시한다.
- 첫 시나리오 화면에 MOTIS, 반복 검증, 기술 진단, 전체 운행조건 폼이 노출되지 않는다.

### 편집

- 첫 화면에서 현행 정류장이 세로 목록으로 읽힌다.
- 정류장 추가·삭제·순서 변경 후 변경 상태와 Before/After diff가 갱신된다.
- 시나리오 라벨을 비워도 자동 라벨로 저장할 수 있다.
- 저장한 시나리오는 기존 프로젝트 재열기 흐름에서 다시 선택할 수 있다.

### 비교와 회귀

- 현행 GTFS와 개편안 GTFS가 같은 OD·출발시각으로 실행된다.
- 기존 GTFS draft, provenance, ZIP export, MOTIS IPC 테스트가 계속 통과한다.
- 입력 변경 후 stale 표시와 재실행 gating이 유지된다.
- `npm run typecheck`, 전체 Vitest, Electron production build가 통과한다.

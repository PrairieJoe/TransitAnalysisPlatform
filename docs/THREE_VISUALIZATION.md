# Three.js 노선 혼잡도 시각화

노선 혼잡도 보고서의 `3D 시각화` 토글은 기존 Leaflet 지도를 보완하는 선택적 탐색 화면입니다. 2D 지도와 표가 보고서의 기준 surface이며, 3D는 피크 재차인원의 공간 패턴과 혼잡 구간을 빠르게 찾는 데 사용합니다.

## 사용 방법

1. 노선 혼잡도 분석을 실행합니다.
2. 상세 도면에서 `3D 시각화`를 선택합니다.
3. 마우스로 이동·확대하고 구간을 클릭해 표의 선택 상태를 동기화합니다.
4. 필요한 경우 `3D PNG 저장`으로 현재 카메라와 선택 상태를 snapshot으로 저장합니다.

`2D 지도`를 선택하면 OpenStreetMap 배경을 사용하는 기존 Leaflet 화면으로 돌아갑니다. 3D 선택 상태와 표 선택 상태는 동일한 구간 키를 사용합니다.

## 시각적 의미

- 구간 색상: 기존 혼잡도 범례(0–10%, 11–20%, 21–30%, 31–40%, 41% 이상)
- 구간 높이: 피크 차내재차인원의 상대 크기
- 정류장 마커: 노선 경로의 정류장 위치
- 회색 구간: 혼잡도 산출 기준이 없거나 유효하지 않음
- 좌표 누락 구간: 장면에서 제외되지만 표와 제외 개수 안내에는 남음

위경도는 장면 안에서 분석 범위 중심의 로컬 미터 좌표로 변환됩니다. 3D 선분은 실제 도로망이나 지형을 의미하지 않는 분석용 기하입니다.

## 접근성·export

캔버스는 시각적 탐색용이며, 정밀 수치와 키보드 선택은 기존 노선 구간 표에서 제공합니다. 색상만으로 혼잡도를 판단하지 않도록 범례와 표를 함께 유지합니다.

3D PNG는 현재 장면의 별도 snapshot입니다. 기존 전체 보고서 PNG/PDF/XLSX export는 2D 보고서 계약을 유지하며 WebGL 지원 여부에 의존하지 않습니다.

## fallback 및 문제 해결

- WebGL2를 사용할 수 없거나 renderer 초기화가 실패하면 안내 메시지와 함께 `2D 지도로 보기`를 선택할 수 있습니다.
- GPU 드라이버나 Electron 환경이 바뀐 뒤 3D가 열리지 않으면 먼저 2D 지도를 사용하고, 동일 환경의 Electron GPU/WebGL 상태를 확인합니다.
- 지도 타일이 없어도 3D 장면 자체는 로컬 데이터로 표시되며, Leaflet 2D 배경 타일 문제와는 별개입니다.
- 3D는 화면을 닫을 때 renderer·geometry·material·controls를 해제합니다. 반복 진입 후 성능 저하가 보이면 mount/unmount cycle과 GPU 상태를 함께 기록합니다.

## 제한 사항

- 현재 파일럿은 노선 혼잡도만 지원합니다.
- OD 흐름·정류장 수요·Synthetic GTFS/MOTIS 경로 애니메이션은 이 화면에 포함하지 않습니다.
- WebGPU backend와 실제 도로망/지형 재현은 별도 검토 대상입니다.

## 설계

전 모드를 사전 계산하면 첫 분석 비용과 메모리가 증가한다. 따라서 실제 선택한 OD 모드만 계산하고 동일 원본 배열·동일 필터의 최대 3개 모드 결과를 캐시한다. 원본 교체/재추정과 필터·분모 변경은 캐시를 무효화한다. 정류장 명칭·좌표는 캐시 사용 후 최신 사전으로 연결한다.

Electron 저장은 기존 `project.json`/`records.duckdb`를 유지하고, 원본 배열이 바뀌지 않은 저장은 `project-state.json`에 records를 제외한 현재 상태만 원자적으로 기록한다. 읽을 때 현재 상태와 원본 records를 결합하고, 전체 저장 시 상태 파일을 초기화한다. 동일 프로젝트 저장을 직렬화한다. `.taproj`는 기존 통합 manifest 계약을 유지한다. 브라우저 IndexedDB는 기존 전체 저장 경로를 유지한다.

## 구현 순서와 검증 계약

1. `tests/core/od-cache.test.ts`, `tests/main/project-store.test.ts`, OD JS/DB 회귀 테스트로 반복 집계 방지, 필터/데이터 무효화, 저장 후 재개, 전체 재저장, 오류 문구 분리를 먼저 재현한다.
2. `src/core/od-cache.ts`와 App OD 실행을 연결한다. 거절된 계산은 캐시에서 제거한다.
3. `src/main/project-store.ts`, main/preload/env, App 저장을 연결한다. metadata IPC로 records가 넘어가지 않으며 DB 쓰기 함수가 호출되지 않아야 한다.
4. `src/core/analysis.ts`, `src/main/duckdb.ts`에서 누락을 우선 분류하고 나머지 순번 오류를 별도 집계한다. 기존 `excludedRows` 합계와 결과 형식을 유지한다.
5. `scripts/benchmark-analysis.mts`로 실제 1일/7일 데이터 측정과 집계 정합성을 기록한다. 원본 개인정보를 결과 파일에 포함하지 않는다.
6. package/lockfile/README/CHANGELOG 버전을 0.6.1로 맞추고 전체 테스트, TypeScript, 빌드, 가능한 배포 smoke를 실행한다. 결과·잔여 제한을 별도 테스트 보고서에 기록한다.

## 완료 판정

회귀 테스트와 빌드 통과, cache hit 결과 정합성, 설정 저장 시 원본 파일 불변, 실데이터 측정값 또는 구체적 차단 사유를 기록한다. 도로망 shape·대규모 MOTIS·7일 UI의 완료 기준은 [확장 구축계획](2026-09-18-v0.6.1-expansion.md)에서 별도로 판정한다. 커밋·원격 배포는 이 계획의 완료 조건이 아니다.

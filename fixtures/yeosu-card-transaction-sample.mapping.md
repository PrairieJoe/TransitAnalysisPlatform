# 여수 거래내역 샘플 매핑

`yeosu-card-transaction-sample.dat`는 실제 거래내역처럼 첫 행에 필드명이 없고 `|`로 구분된 28개 필드입니다. 앱은 첫 행의 날짜·통합일시 값 형식을 확인해 헤더 없음 상태를 자동 제안하며, 다음 연결을 기본값으로 제안합니다.

| 앱 분석 역할 | 샘플 필드 | 테이블 정의서 위치 |
| --- | --- | --- |
| 날짜 | `필드1` | 운행일자(1) |
| 시간 | `필드15` | 승차일시(15) |
| 승차인원 | `필드25` | 이용자수(25) |
| 정류장 ID | `필드17` | 승차정류장ID(국토부표준)(17) |
| 하차 정류장 ID | `필드20` | 하차정류장ID(국토부표준)(20) |
| 노선 | `필드13` | 노선ID(국토부표준)(13) |
| 지역 | `필드5` | 정산지역코드(5) |

정류장 수요 분석은 표준 승차 정류장 ID인 `필드17`을 사용하고, OD 분석은 여기에 표준 하차 정류장 ID인 `필드20`을 추가로 사용합니다. 정류장 정보 파일을 별도로 불러온 뒤, 해당 파일의 정류장 ID·명칭·위도·경도를 연결해야 합니다. 샘플에는 어떤 정류장 정보 파일과도 연결되지 않는 승차 정류장 ID `999999999`도 한 건 넣어 사전 미등록 경고를 확인할 수 있게 했습니다.

운행일자 필드가 누락되거나 값이 비어 있는 원천 파일은 승차 통합일시 값에서 날짜를 추출합니다. 원천 열 자체가 이동한 경우에는 날짜·통합일시·정류장 ID·이용자수의 값 형식으로 위치를 추정하므로, 자동 제안 후 화면에서 반드시 확인할 수 있습니다.

동일 지역으로 수요 지도까지 확인하려면 `yeosu-station-master-sample.dat`를 함께 선택하세요. 이 파일은 정류장정보 14필드 원천 구조이며 `필드4=정류장 ID`, `필드5=정류장 명칭`, `필드7=위도`, `필드8=경도`입니다.

카드번호·차량등록번호·거래번호·이용 수치·좌표는 모두 테스트용 합성값입니다. 실제 운영 데이터의 개인정보·민감정보를 샘플에 복사하지 마세요.

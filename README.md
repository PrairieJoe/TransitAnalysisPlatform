# Transit Analysis Platform

현재 소스 버전은 **0.7.0**입니다. [0.6.2 Custom MOTIS 소스 체크포인트](docs/releases/0.6.2.md)를 기반으로 기능 통합과 32-way Custom MOTIS artifact 포함 검증을 완료했습니다.

교통카드 CSV/DAT/TXT/XLSX 파일을 불러와 요일별·시간대별·정류장별·OD별 수요, 노선 혼잡도와 데이터 오류 유형을 분석하는 Windows 설치형 데스크톱 앱입니다.

## 주요 기능

- 여러 파일 가져오기와 필드 매핑
- 파일 클릭 또는 드래그앤드롭으로 가져오기
- 상위 10개 행 데이터 미리보기
- 첫 행이 필드명인 파일과 필드명이 없는 파일 모두 지원
- 필드명이 없는 표준 거래내역의 위치·값 형식 기반 자동 매핑
- 이용인원 합계/통행량(행 수) 구분 집계
- UTF-8/CP949 계열 텍스트 자동 인식 및 구분자 미리보기
- 실제 관측일/전체 날짜 기준 평균 계산
- 노선·정류장·지역 필터
- 첨부 이미지 형식의 그래프와 표
- 통합 일시 또는 날짜·시간 분리 필드 기반의 주중·주말 0–23시 분석
- 7–8시·17–18시 고정 첨두시 음영과 시간 정보 누락 경고
- PNG·PDF·XLSX 내보내기
- 로컬 프로젝트 저장 및 `.taproj` 백업
- 정류장 수요 분석용 정류장 정보 파일 입력·필드 매핑 및 프로젝트 저장
- 승차–하차 정류장 OD 통행량 집계, 지도 흐름선·방향 화살표·순위표
- 노선별 정류장 순서 기반 구간 재차인원·혼잡도 분석, 시간대 선택·노선 도면·운행 기준 입력
- 분석 지표별 원 단위/천 명 단위 표시 전환
- 승차·하차·노선·순번 오류 8개 유형의 통행량·이용인원 집계 및 기간·노선 필터
- 보고서 화면의 현재 분석별 데이터 활용 기준과 포함·조건부·제외 상태 안내
- 노선별 운행 기준표 검색·독립 스크롤·고정 헤더
- 노선별 운행 기준 전체와 운행횟수 일괄 입력의 접기·펼치기
- `ⓘ` 포커스형 필드 설명 툴팁
- 긴 분석 경고의 접이식 요약과 작업 실패 원인 안내
- 노선 혼잡도 상세 도면의 선택적 Three.js 3D 시각화 및 PNG snapshot
- 원본 하차 ID를 보존하는 Trip-Chain·거리·노선 제약 기반 하차누락 추정
- Before/After Synthetic GTFS 생성과 내장 MOTIS 시간표·OD 비교
- Geofabrik 대한민국 PBF 링크 열기와 앱 내 PBF 파일 선택·검증

거래내역 자동 매핑은 필드명이 없어도 표준 위치와 값 형식을 함께 확인합니다. 운행일자 필드가 없거나 값이 비어 있으면 승차 통합일시 필드에서 날짜를 추출하고, 실제 파일에서 열이 이동한 경우에도 날짜·통합일시·정류장 ID·이용자수의 값 패턴을 기준으로 위치를 보정합니다. 자동 제안은 항상 가져오기 화면에서 수정할 수 있습니다.

여수시와 같은 실제 28필드 DWTCD 원천에서 국토부 표준 노선·정류장 ID(필드13·17·20)가 비어 있고 정산사 ID(필드14·18·21)만 채워진 경우에는, 앱이 값이 존재하는 정산사 ID를 노선·승차·하차 연결값으로 자동 제안합니다. 비식별화된 가상카드번호(필드4), 트랜잭션 ID(필드22), 환승건수(필드23)는 Trip-Chain과 중복행 확인을 위해 원문 값으로 보존할 수 있습니다.

## 정류장 수요 분석 입력

정류장 수요 분석은 교통카드 파일과 별도로 `정류장 정보 파일`을 같은 가져오기 화면에서 선택하고 필드를 연결해야 사용할 수 있습니다. 앱에는 기본 정류장 사전을 번들하지 않습니다. 분석별로 불러온 정류장 정보만 해당 프로젝트에 저장·복원합니다.

정류장 정보 파일에서 다음 네 가지 필드를 연결합니다.

- 정류장 ID: 교통카드 데이터의 정류장 ID와 정확히 일치해야 합니다.
- 정류장 명칭
- 위도·경도: 십진수 좌표

헤더가 없는 원천 DAT 파일도 지원하며, 예시 정류장 정보의 경우 `필드4=정류장 ID`, `필드5=정류장 명칭`, `필드7=위도`, `필드8=경도`로 연결합니다. 좌표가 잘못되거나 중복된 ID는 해당 행만 제외하고 경고합니다. 사전에 없는 교통카드 정류장 ID는 표에 `사전 미등록`으로 남고 지도에서는 제외됩니다.

거래내역과 바로 연결해 볼 수 있는 동일 지역 샘플 조합은 다음과 같습니다.

- 거래내역: `fixtures/yeosu-card-transaction-sample.dat`
- 정류장정보: `fixtures/yeosu-station-master-sample.dat`

두 파일은 여수시 정류장 ID 체계를 공유하며, 거래내역에 의도적으로 포함한 `999999999` 한 건만 사전 미등록 경고 확인용입니다.

## OD 통행량 분석

OD 분석은 거래내역의 승차 정류장 ID와 하차 정류장 ID를 한 쌍으로 묶어 선택 기간의 일평균 수요를 계산합니다. 실행하려면 다음 세 가지가 필요합니다.

1. 거래내역의 `승차 정류장 ID`와 `하차 정류장 ID` 필드 연결
2. 정류장 정보 파일의 ID·명칭·위도·경도 연결
3. 분석 조건 적용 후 `OD 흐름` 탭 선택

표준 28필드 거래내역은 `필드17=승차 정류장 ID`, `필드20=하차 정류장 ID`를 자동 제안하지만, 자동 제안값은 가져오기 화면에서 직접 확인·수정할 수 있습니다. 두 ID 중 하나라도 비어 있는 행은 OD 집계에서 제외하고 경고합니다. ID가 거래내역에는 있으나 정류장 정보 파일에 없는 경우에는 표에 `사전 미등록`으로 남기며 지도 흐름에서는 제외합니다.

지도는 모든 집계된 OD 흐름을 표시합니다. 흐름선은 승차 지점에서 하차 지점으로 향하는 정적 곡선이며, 일평균 수요가 많을수록 굵어지고 삼각형 화살표는 하차 방향을 나타냅니다. 서로 반대 방향인 흐름은 같은 구간에서 반대쪽 곡선으로 분리하고, 동일 정류장 간 흐름은 자기고리 형태로 표시합니다. 지도 배경 타일을 불러오지 못해도 흐름선은 계속 표시됩니다. 표의 행을 선택하면 해당 흐름을 강조하고, 표 제목을 누르면 정렬합니다.

## 하차누락 추정

노선별 경유정류장정보가 연결된 경우 `입력 완료 → 하차 추정`에서 원본 하차 ID를 덮어쓰지 않는 추정 레이어를 생성합니다. 같은 가상카드의 다음 승차 기록, 정류장 좌표 거리, 노선 순번과 종점 제약을 조합해 `고신뢰 추정`과 `기대값 추정`을 구분합니다.

하차 추정 실행 후 기본 화면은 요일별 분석으로 이동합니다. 추정 결과의 커버리지는 상단 `추정 방법 설정`에서 확인하고, `OD 흐름` 또는 `노선 혼잡도` 탭의 `하차 추정값 사용`에서 관측값·고신뢰 추정·기대값 포함 범위를 선택합니다. 요일별 분석과 정류장 수요는 원본 관측값 기준이며, 추정값 선택은 OD·노선 분석에만 적용됩니다.

OD의 상세 입력·집계·지도 표현·예외 처리 기준은 [`docs/OD_ANALYSIS.md`](docs/OD_ANALYSIS.md)에 기록되어 있습니다.

## 교통카드 데이터 품질 분석

보고서의 `데이터 품질 현황` 탭은 날짜·이용인원이 유효한 거래를 대상으로 정류장정보와 노선별 정류장정보를 대조합니다. 다음 8개 유형을 한 행에 여러 개 중복 판정할 수 있으며, 표에는 프로젝트 집계 기준에 따른 전체 통행량/이용인원, 정상 값, 중복을 제외한 오류 값을 표시합니다.

- `승차누락`, `하차누락`: 거래내역의 승차·하차 정류장 ID가 비어 있는 경우
- `승차매칭불가`, `하차매칭불가`: 통합 정류장 목록에 해당 ID가 없는 경우
- `노선누락`, `노선매칭불가`: 거래내역의 노선 ID가 없거나 노선정보에서 찾을 수 없는 경우
- `노선경유정류장매칭오류`: 해당 날짜에 적용된 노선 경로에서 승차·하차 정류장을 찾을 수 없는 경우
- `경유정류장순번오류`: 승차 정류장이 하차 정류장보다 뒤에 있거나 순방향 경로로 연결되지 않는 경우

요일별 분석은 날짜·이용인원이 유효한 행을 모두 포함하고, 시간대 분석은 유효한 승차 시간이 있는 행만 포함합니다. 정류장 수요는 승차 ID가 필요하며, OD는 승차·하차 ID와 순번 오류가 없는 행만 사용합니다. 노선 혼잡도는 노선 ID·승차·하차·시간과 적용 가능한 날짜별 경로가 필요하며, 순번 오류 거래는 제외합니다. 각 기준은 보고서의 `현재 분석의 데이터 활용 기준 보기` 패널에서 포함·조건부·제외 상태로 확인할 수 있습니다.

## 노선별 시간대 혼잡도 분석

노선 차내재차인원은 교통카드 거래내역과 별도의 `노선별 정류장정보 파일`을 결합해 계산합니다. 거래내역에는 노선 ID, 승차 정류장 ID, 하차 정류장 ID, 승차시각이 필요하며, 차량별 최대값을 계산하려면 차량 ID도 연결해야 합니다. 노선정보에는 노선 ID·명칭·교통수단·정류장 순번·정류장 ID·명칭·위도·경도가 필요합니다. 차량 정원과 0–23시별 1일 운행횟수는 분석 결과 화면의 `노선별 운행 기준` 표에 입력하며, 동일한 값이 필요한 경우 `운행횟수 일괄 입력`으로 모든 노선의 전체 시간대에 적용할 수 있습니다.

혼잡도는 다음 기준으로 계산합니다.

정류장별 차내재차인원은 노선 진행 순서에 따라 `이전 재차인원 + 승차인원 - 하차인원`으로 누적합니다. 차량 ID가 있으면 차량·날짜·시간대별 누적값 중 최대값을 사용하고, 차량 ID가 없으면 시간대별 집계값을 운행횟수로 나눈 평균 재차인원 추정치를 사용합니다. 혼잡도는 `최대 차내재차인원 ÷ 차량 정원 × 100`으로 계산합니다.

승차 정류장과 하차 정류장을 노선 순번에 매칭해 순방향 거래만 노선 재차인원에 반영하고, 순번이 역방향인 거래는 오류로 분류해 제외합니다. `전체 시간대`는 0–23시 각 시간대의 차량/평균 프로필 중 최대값을 사용합니다. 차량 정원 미입력 또는 차량 ID가 없는 상태에서 운행횟수가 0이면 혼잡도를 `—`로 표시하고 산출 제외·추정 경고를 함께 제공합니다. 범례는 0–10%, 11–20%, 21–30%, 31–40%, 41% 이상입니다.

헤더가 없는 공유 형식 14필드는 다음 위치로 자동 연결됩니다.

`필드1 운행일자 · 필드4 노선 ID · 필드5 노선 명칭 · 필드6 교통수단구분 · 필드7 정류장 순번 · 필드8 정류장 ID · 필드9 정류장 명칭 · 필드10 위도 · 필드11 경도`

운행일자가 있으면 거래일과 정확히 일치하는 경로를 우선 사용하고, 날짜가 없는 정적 경로는 전체 기간에 재사용합니다. 단일 날짜 경로를 다른 날짜에 재사용하거나 순번·필수값·정류장 중복 오류가 있으면 화면에 경고합니다. 결과에서는 전체 노선 요약표와 선택 노선의 정류장 순서 도면을 제공하며, 현재 선택 노선 결과는 PNG·PDF·XLSX(`노선혼잡도` 시트)로 내보낼 수 있습니다.

거래내역과 바로 연결해 볼 수 있는 노선 샘플 조합은 다음과 같습니다.

- 거래내역: `fixtures/yeosu-card-transaction-sample.dat`
- 노선별 정류장정보: `fixtures/yeosu-route-station-master-sample.dat`

노선 상세 도면의 `3D 시각화`는 기존 Leaflet 지도를 보완하는 선택 기능입니다. WebGL2를 사용할 수 없는 환경에서는 2D 지도로 fallback하며, 시각적 탐색 외의 정밀 수치·키보드 선택은 기존 표에서 제공합니다. 자세한 사용법과 제한 사항은 [`docs/THREE_VISUALIZATION.md`](docs/THREE_VISUALIZATION.md)를 참고하세요.

## Synthetic GTFS와 MOTIS

분석 결과 화면의 `GTFS 구축`에서 노선별 운행대수·첫차·막차·배차간격을 입력해 Before/After GTFS를 만들 수 있습니다. After 경로의 정류장 ID를 수정하면 제거·추가 정류장과 생성 Trip 수를 비교할 수 있으며, 생성 결과는 Synthetic 데이터라는 점이 화면에 표시됩니다.

MOTIS는 Windows 배포본에 내장되어 앱이 실행 파일·작업 폴더·포트를 자동 관리합니다. OSM 도로·보행 routing을 사용하려면 Geofabrik에서 받은 지역 PBF를 Builder에서 선택합니다. PBF는 배포 파일에 포함하지 않으므로 지역별로 별도 준비해야 하며, 지도 타일이 없어도 GTFS·MOTIS 분석은 실행할 수 있습니다.

## 실제 여수시 데이터 검증

실제 여수시 원천 데이터는 다음 구조로 제공됩니다.

- 거래내역: `DATA_YYYYMMDD/DWTCD_YYYYMMDD.dat`
- 정류장정보: `DATA_YYYYMMDD/STTN_YYYYMMDD.dat`
- 노선별 정류장정보: `DATA_YYYYMMDD/ROUTESTTN_YYYYMMDD.dat`

처음에는 하루분을 선택해 매핑과 처리시간을 확인한 뒤, 여러 날짜 파일을 추가합니다. 2024-04-15 기준 거래내역은 약 105,412행·15.9MB이며, 2024-04-15~21 일주일 거래내역은 약 109.8MB입니다. 실제 검증 결과와 알려진 제한은 [`2026-09-18 여수시 실데이터 검증 보고서`](docs/test-reports/2026-09-18-yeosu-real-data-validation.md)에 정리되어 있습니다.

## 개발

Node.js 20 이상과 npm이 필요합니다.

코드 병합과 Custom MOTIS Release asset 발행은 별도 단계입니다. 버전 배포 시
[`docs/release-process.md`](docs/release-process.md)의 체크리스트를 먼저 확인합니다.
다른 환경에서 이어서 개발할 때는 [`docs/development-resume.md`](docs/development-resume.md)의 clone·bootstrap 절차를 사용합니다.

```powershell
npm install
npm test
npm run typecheck
npm run dev
```

## 버전

현재 작업 버전: `0.7.0` (정식 릴리스, 2026-09-21)

0.7.0은 Custom MOTIS 소스 기반과 시나리오 편집·실행·비교·수요 추정 기능을 통합한 정식 릴리스입니다. 32-way 후보의 실제 데이터·경계 검증, 앱 회귀 테스트·typecheck·production build, 배포 가능한 component artifact 포함 및 packaged app smoke를 완료했습니다. 상세 결과는 [0.7.0 릴리스 기록](docs/releases/0.7.0.md)을 참고하세요.

0.6.0은 하차누락 추정, 선택형 3D 노선 시각화, Synthetic GTFS·내장 MOTIS 연계와 기존 분석 기능을 통합한 동결 버전입니다. 내부 `quality` 분석 모드와 기존 프로젝트 스키마는 유지합니다.

0.6.1은 OD 추정 모드별 결과 캐시, 원본 DB 재기록 없는 분석 설정 저장, 누락 ID·순번 오류 안내 분리를 적용합니다. 같은 데이터·필터에서 한 번 조회한 모드는 재집계 없이 재사용하고, 원본·필터·분모가 바뀌면 캐시를 초기화합니다. Electron 프로젝트의 `project-state.json`에는 최신 설정·분석 결과가 저장되므로 폴더를 직접 복사할 때 함께 보존해야 합니다. `.taproj` 내보내기는 최신 상태와 원본을 하나로 포함합니다. 브라우저 개발 모드의 IndexedDB 저장 방식은 기존과 같습니다.

문서 미결사항과 후속 범위는 [0.6.1 구축계획](docs/plans/2026-09-18-v0.6.1-stabilization.md), 검증 결과는 [0.6.1 테스트 보고서](docs/test-reports/2026-09-18-v0.6.1-validation.md)에서 확인합니다.

여수시 실데이터 화면별 캡처와 사용자 확인 항목은 [여수시 Computer-use 보고서](docs/test-reports/2026-09-19-yeosu-computer-use-report.docx), 이후 캡처 기준은 [Computer-use 보고서 작성 지침](docs/test-reports/computer-use-reporting-guidelines.md)에 기록했습니다.

추가 요청에 따라 도로망 shape, 대규모 MOTIS matrix, 실제 7일 UI 검증도 [0.6.1 확장 구축계획](docs/plans/2026-09-18-v0.6.1-expansion.md)에 포함했습니다. 노선 상세의 `도로망 형상`에서 OSM BUS 경로를 2D·3D 도면에 적용할 수 있습니다. 연결 실패 구간은 직선 대체로 표시하며, 수요·혼잡도 계산값은 유지합니다. 사용법과 제한은 [3D·도로망 문서](docs/THREE_VISUALIZATION.md)를 참고하세요.

## Windows 배포

배포 파일은 다음 명령으로 생성합니다.

```powershell
npm run package:win
```

현재 설치 파일은 `release/TransitAnalysisPlatform-0.7.0-setup.exe`에 생성되며, 수동 실행 검증용 압축 해제본은 `release/win-unpacked`에 둡니다. 패키징 중간 산출물인 `release/win-unpacked.tmp`와 `out/electron-dist`는 패키징 스크립트가 정리합니다.
